## Corrections to the PRD

- **`SqliteDatabase` is asynchronous and has seven methods.** Section 2 lists `exec`, `run`, `get`, `all`,
  `transaction`, `close`. The interface (Chord's, re-exported by Pi Durable) also requires `runCounted`, and every
  method returns a promise. Rivet's promise-based `c.db` therefore fits; `@rivet-dev/pi` implements exactly this.
- **The Rivet host cannot be written on `@rivetkit/effect` alone** (section 5.2, decision 13.4). It needs the raw
  `actor()` config for `onFork` and the raw client for `fork`. Options: write the host on raw `rivetkit` and register
  it through `Registry.rivetkitActors`, or ask Rivet to forward both. The fork depth limit of 16 appears in none of
  the three packages; it is presumably enforced by the engine.
- **`@rivet-dev/pi` 0.5.7 cannot be reused**: its peer range `~1.5.0` excludes Pi Durable 1.6.0. It is a good
  reference: one `pi.wake` action kept scheduled at the earliest sleep, `keepAwake` while work runs, a `pi_` table
  prefix.
- **`npm run check` needs model data first.** On a fresh clone it fails with about 1,000 type errors until
  `npm run hydrate:model-data` (or `npm run build`) has fetched the gitignored model catalog. Not caused by us.
- **Upstream versions its packages in lockstep.** `scripts/sync-versions.js` fails when the public packages of
  `packages/` differ in version, and upstream's publish scripts publish all of them. Our packages are at 0.1.0, so
  upstream's `version:*` and `publish` scripts must never run in the fork; we need our own (section 9.5, not built).
- **Two root lines were needed, not zero.** `tsconfig.json` gets two `paths` entries (`effect/boundary.json` says
  why). No change to `vitest.base.ts`, `biome.json` or `package.json` was needed.
- **`@effect/vitest` cannot be used**: 4.1.5 requires Vitest 5, upstream pins 4.1.12.
- **tsrs brings nothing yet.** `tsrs 7.1.0-beta.tsrs5` type checks our packages in 0.06 s; upstream's TypeScript 7
  `tsc` takes 0.10 s on the same program and is the compiler the upstream check uses. Both caught a planted error.
  The fast lane therefore uses `tsc -p effect/tsconfig.json`, and tsrs is not installed. Revisit when the packages
  are large enough for it to matter.

## What cannot cross the model bridges

- Effect serves Pi: request options (`temperature`, `maxTokens`, reasoning level) stay with the Effect layer; Pi's
  replay signatures for reasoning are dropped; provider-executed tool calls, files and sources of a response are
  dropped so Pi never runs a call twice.
- Pi serves Effect: `generateObject`, a forced tool choice, non-image files and image URLs fail with
  `InvalidRequestError` before any request; Pi's cost is not in the response parts; a Pi error arrives as an
  `AiError` with reason `UnknownError`, because Pi reports only text.

## What Pi Durable does that the plugins must know

Found by the kill-and-resume and interruption suites of `durable-effect`:

- A model request stopped by a close is sent again on reopen.
- A `replay: "unsafe"` tool is never run again: a close during the call, or during its `afterTool` hook, leaves an
  `interrupted` error result, even when the handler had finished. A `replay: "safe"` tool runs again.
- Interrupting the caller never stops the run. An input interrupted during admission is still admitted and answered;
  the same `requestId` finds it.
- A failing hook is reported and skipped, and the run continues. `beforeTool` is the exception: the call is blocked.
  A guard must therefore deny in `beforeTool` or at registry construction, never in a hook that fails open.

This file is what milestone 0 found. The state after milestones 1 to 4 is in `effect/COMPAT.md` (packages and test

Later findings that correct the above:

- **A hook cannot commit**, so the recorder's pending rows cannot join a step's commit as PRD section 7 words it.
  The entries are the outbox: a record is derived from a committed entry, and a cursor document says how far
  delivery got.
- **A generation hook cannot stop a provider request** (a failing hook is skipped). The budget's lease and the
  router's ceilings are therefore enforced at the model boundary, by wrapping `Models`, not by hooks.
- **Pi cannot delete a conversation.** An in-storage swarm fork is aborted and marked destroyed; its entries stay.
- **Rivet 3.1.1**: `rivetkit`'s `db.transaction` isolates but does not queue other statements, so the host queues;
  the engine binds its port, the next one and the tenth after it; a refusal can carry `retry_after_ms`
  (`depot.overloaded`), which the host honours; rivetkit calls `process.exit(1)` a minute after a local engine start
  that got no healthy engine, which the host's local engine holds back; on Bun an assignment to `process.env` does
  not reach rivetkit's native core, so the `/bun` entry sets `RIVETKIT_STORAGE_PATH` with `setenv`.
- **The host's fork rule**: a fork is refused for an unsettled submission and for a live task that is not a
  background task of the product. What a copy can inherit live is ended by each plugin's `onStorageFork`.
